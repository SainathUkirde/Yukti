# Well-to-Surface Digital Twin
## CSS + SRP Optimization — Baghewala Heavy Oil Field
### Smart India Hackathon (SIH) Demo

---

> ⚠️ **Data Disclaimer:** All operational data in this prototype is physics-based synthetic,
> generated by the built-in simulator and calibrated to published petroleum engineering literature.
> This prototype has **not** been validated on real Baghewala field operations.
> Every number in the UI and API carries a provenance label.

---

## Quick Start

### Option A — Docker (recommended, one command)
```bash
docker compose up
```
- Frontend: http://localhost:5173
- Backend API: http://localhost:8000
- API Docs: http://localhost:8000/docs
- Offline check: http://localhost:8000/offline-check

Pre-generated data and pre-trained models are included. If absent, they are auto-generated on first boot (~2 min).

### Option B — Local (no Docker)
```bash
# Backend
python -m venv .venv
.venv/Scripts/activate          # Windows
# source .venv/bin/activate     # Linux/Mac
pip install -r backend/requirements.txt
python data/generate.py         # Generate synthetic datasets
cd backend && uvicorn app.main:app --reload --port 8000

# Frontend (new terminal)
cd frontend
npm install
npm run dev
```

### Makefile targets
```bash
make setup          # Install all dependencies
make generate-data  # Generate synthetic datasets
make train          # Train ML models
make run-dev        # Start dev servers (backend + frontend)
make test           # Run all unit tests
make build          # Production build
make offline-check  # Verify everything runs without internet
```

## Architecture

```
Reservoir → Wellbore → SRP → Surface
    ↓            ↓        ↓       ↓
Physics Simulator (full + fast surrogate)
    ↓
ML Layer (forecast + fault classification + risk)
    ↓
Joint Optimizer (CSS + SRP together, Optuna)
    ↓
Constraint Engine (all recommendations verified)
    ↓
FastAPI + WebSocket
    ↓
React Dashboard (dark SCADA theme)
```

See [`docs/architecture.md`](docs/architecture.md) for full detail.

## Provenance Badge System

Every number carries one of these badges:

| Badge | Color | Meaning |
|---|---|---|
| FIELD_FACT | 🟢 Green | Real verifiable field fact |
| LITERATURE_ASSUMPTION | 🔵 Blue | Published literature parameter |
| SYNTHETIC_HISTORICAL | 🟣 Purple | Simulator-generated history |
| SIMULATED_LIVE | 🟡 Amber | Live simulator tick |
| ML_PREDICTION | 🔵 Cyan | ML model output with uncertainty |
| OPTIMIZER_RECOMMENDATION | 🟠 Orange | Joint optimizer output |
| DEMO_RESULT | 🔴 Red | Baseline vs optimized comparison |

## Demo Features

- 🎬 **Guided demo mode**: Normal → Cooling → Rod Floating detected → Auto-fix → Savings
- ⚡ **Fault injection**: Simulate rod floating, pump-off, gas interference, fluid pound
- 🔮 **What-if engine**: Change any parameter, see full physics propagation
- 📊 **Baseline vs Optimized**: Paired simulator runs (labeled DEMO_RESULT)
- 🤖 **AI assistant**: Local rule-based explainer (no internet required)
- 📄 **PDF report**: One-click cycle summary, generated locally

## Environment Variables

Copy `.env.example` to `.env`. The app runs with zero configuration using defaults.

```env
# Backend
DATABASE_URL=sqlite:///./digital_twin.db
CORS_ORIGINS=http://localhost:5173
TICK_INTERVAL_S=1.5
TIME_ACCELERATION=10
LOG_LEVEL=INFO

# Frontend
VITE_API_URL=http://localhost:8000
VITE_WS_URL=ws://localhost:8000

# Optional enhancements (not required)
OPENAI_API_KEY=         # If set, enables LLM assistant
VOLVE_DATA_PATH=        # If set, calibrates sensor noise from Volve data
USE_CNN_CLASSIFIER=false  # Set true to use optional CNN for dyno cards (requires torch)
```
